# Finite arguments used by the volume proofs

This package contains the finite polynomial, support and sector lemmas
used in the active [volume reference](../manuscript/README.md).
The actual complex estimates and Conway assembly are in
[formal-real](../formal-real/README.md). The packages use the same
pinned Lean toolchain.

The [coverage map](coverage.json) names the retained manuscript
statement and public proof roots for every module. It also records why
the module is needed. The active library contains no recurrence,
moving-meridian or formal-gauge branch.

## The finite proof components

| Component | Use in the reference |
| --- | --- |
| FiniteAlgebra and the MonicRemainder, MonicLinearity, MonicUniqueness, MonicProduct modules | Construct the canonical polynomial remainder, prove its degree, uniqueness and representative independence, and reduce products while retaining first derivatives at repeated roots. These are the canonical-remainder propositions in the filling-functional appendix. |
| ResolventFunctional | Construct the polynomial resolvent and prove the top-coefficient reproduction identity. No division by the difference of two roots is used. |
| FiniteSupport | Partition the central and two one-sided cofactor supports, with their actual even- and odd-level endpoint cutoffs. |
| FaceGridSupport | Prove the unique exponent target from the ordinary residues and homogeneous degree budget after Fourier selection. |
| SourceAssembly | Apply the additive filling to the exact coherent sector sum before taking norms; retain every sector and multiplicity. |
| RateComparison | Combine the scalar entropy gain, quadratic cost and final strict rate loss. |
| ProtectedSum and TriangularBoundary | Prove the protected-sum and ordinary-insertion comparisons with their duplicated targets and whole-block cases. |

The scalar polynomial statements use ascending coefficient lists over
a commutative ring. In the local matrix application, that ring is the
commutative algebra generated by the one specified Casimir. This does
not assert that operators at different crossings commute. The actual
physical source identity and the geometric constructions have their
written proofs in the reference and its named companions.

## Compile and audit

The complete retained formalization is checked from the repository root:

~~~sh
python3 repro/check_lean.py --output repro/results/volume-lean
~~~

The runner builds this Std-only library first, then the selected
Mathlib modules. It rejects unregistered local imports, inventories
every public definition and theorem, and checks their logical axioms.
It removes only the projects' generated local build directories before
compiling; the pinned shared dependencies are left intact.

For this package alone, ordinary Lean commands are also available:

~~~sh
cd formal
lake build
lake env lean AxiomAudit.lean
~~~

The main replay additionally checks manuscript anchors, configuration,
source hashes and the complete active source inventory. These checks
keep the code aligned with its declared statements; the kernel proves
the Lean statements themselves.

The [cleanup record](../repro/PROOF_PATH_CLEANUP_2026-11-25.md) records
the manuscript-first revision and the current verification results.
